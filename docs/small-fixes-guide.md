## 2. `handleDragEnd` のガード

### 何をするか

次の 2 つの場面では、**並び替えも API の呼び出しもせずに、すぐ終わる**ようにする。

| 場面 | 例 |
| --- | --- |
| A | 何もない場所（並び替えられる場所の外）で離した |
| B | つかんだノートを、元と同じ位置で離した |

### 今のコードについて考えてほしいこと

今は、`reorderNotes` を呼んだ**あと**に、`if (!Number(event.over?.id)) return;` が書いてあります。

| 問い |
| --- |
| ガードは、関数の中のどこに書くのがよい？（計算のあと？ 前？） |
| A のとき、`event.over` の中身は何になる？ そのとき `Number(event.over?.id)` は何になる？ |
| B は、今のガードで防げている？ |
| B を防がないと、何が起きる？（API の呼び出しに注目） |

> **用語メモ**：**ガード節（早期リターン）**とは、関数の最初で「この場合は何もしない」を `return` で先に抜けておく書き方です。本題の処理を、`if` の中に深く入れずに済みます。

## 4. 元の配列を書き換えないことのテスト

### 何をするか

`reorderNotes` に配列を渡して呼んだあと、**渡した元の配列が、呼ぶ前と同じまま**であることを確かめるテストを 1 つ足す。

> **なぜ大事か**：楽観的更新で失敗したとき、元の並び（`preOrderedNotes`）に戻します。もし `reorderNotes` が元の配列を書き換えていたら、戻す先も変わってしまい、元に戻せません。

---

## 5. テストの名前

### 何をするか

「ドラッグして移動せずに落とす」という名前が 3 つあります。中身を見て、**名前だけで、どの場面を確かめているかがわかる**ように直す。

| 今の 3 つ | 中身 |
| --- | --- |
| 1 つ目 | 2 を 2 の上に落とす |
| 2 つ目 | 一覧にない 9 を、1 の上に落とす |
| 3 つ目 | 1 を、一覧にない 9 の上に落とす |

> **なぜ大事か**：テストが落ちたとき、画面に出るのは名前だけです。同じ名前が 3 つあると、どれが落ちたのかがわかりません。
